# Epistula 1.0.1

Epistula 1.0.1 brings the five services up to date with Go 1.27.4, pgx 5.12.0,
updated dependencies, and GoReleaser 2.20.0. It includes the security and
reliability fixes accumulated since 1.0.0.

Highlights:

- Improve IMAP synchronization, command pacing, FETCH error handling, and
  connection limits. Add `admin folder-resync` to refresh clients after a
  repaired folder leaves stale cached state.
- Strengthen blob durability, delivery retries, mailbox isolation, recovery,
  archive sorting, and worker retry handling.
- Reduce database storage and query work with migrations 023–030, expression
  search indexing, indexed IMAP status queries, and mailbox-scoped annotation
  queues. The API derives HTML bodies from the original message blobs.
- Add attachment downloads to the API and MCP connector, plus optional
  outbound submission with separate credentials and mailbox permissions.
  Submission remains disabled until configured.
- Fix Linux package installation ordering and FreeBSD service shutdown.

Upgrading from 1.0.0 requires configuration and schema checks:

1. Back up PostgreSQL and the blob store together. Run `check-config` with
   the new database, IMAP, API, and worker executables against their deployed
   configurations. Unknown TOML keys now fail validation in all five services,
   and PostgreSQL DSNs follow pgx's updated parsing rules.
2. Using the new database executable, apply the additive migrations first:
   `epistula-database migrate up -to 29 -timeout 0`.
3. Deploy the matching database, IMAP, and API executables, then run
   `epistula-database migrate up` to apply migration 030. Finish replacing
   every old database writer and reader before this final step: it drops
   columns used by the old executables. Index builds can take time on large
   stores; see [the rollout guide](https://github.com/ptudor/epistula-mail/blob/v1.0.1/DATABASE_OPERATIONS.md#rolling-the-schema-change-out).
4. Update dashboards for `mail_database_messages_estimate` and
   `mail_database_gc_candidates_estimate`. Review explicit
   `purge_all_copies = true` settings: the new default is `false`, preserving
   copies outside the eligible Trash rows.

IMAP `SEARCH BODY` and `SEARCH TEXT` now search the text projection; terms
found only in an HTML alternative or its markup no longer match. Dropping
the old columns does not itself reclaim disk space; the database operations
guide describes optional space reclamation.
